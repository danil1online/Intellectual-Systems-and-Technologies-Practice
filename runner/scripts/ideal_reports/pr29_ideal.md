Открыл веб-интерфейс Langflow по адресу `http://<host>:7860`, авторизовался под учётной записью администратора. На главном рабочем столе нажал кнопку **New Flow** → **Blank Flow**, переименовал проект в `Практическая 29 - Базовый Чат-бот`.

### Шаг 2. Размещение компонентов на холсте

Из боковой панели перетащил на холст четыре компонента:

1. **Inputs & Outputs → Chat Input** — приём текста пользователя;
2. **Models & Agents → Prompt Template** — формирование промпта с системной инструкцией;
3. **Models & Agents → OpenAI (Language Model)** — подключение к языковой модели;
4. **Inputs & Outputs → Chat Output** — вывод ответа модели.

### Шаг 3. Конфигурирование компонента модели

Параметры компонента **OpenAI**:

| Параметр | Значение |
|---|---|
| OpenAI Base URL | `http://192.168.2.83:8080/v1` |
| Model Name | `qwen2.5-3b-instruct-q4_k_m.gguf` |
| OpenAI API Key | `not-needed` |
| Temperature | `0.7` |
| Stream | `True` |

Суффикс `/v1` в Base URL обязателен: это версионирование OpenAI-совместимого API, без него сервер llama.cpp не находит нужный маршрут.

### Шаг 4. Настройка шаблона промпта

В компоненте **Prompt Template** задан шаблон:

```text
System: Ты — квалифицированный ассистент кафедры интеллектуальных систем. Отвечай строго, четко и структурировано на русском языке.

User: {user_message}
```

При объявлении переменной `{user_message}` в фигурных скобках Langflow автоматически создал входной порт `user_message` у компонента Prompt.

1. `Text` (Chat Input) → `user_message` (Prompt);
2. `Prompt Text` (Prompt) → `Input Value` (OpenAI Model);
3. `Text` (OpenAI Model) → `Text` (Chat Output).

Один и тот же вопрос «Придумай 3 оригинальных названия для лабораторного робота-помощника» отправлен три раза при разных значениях Temperature:

## Контрольные вопросы

1. **За что отвечает параметр Base URL при настройке компонента модели в Langflow и почему для llama.cpp используется суффикс /v1?**
   Base URL задаёт адрес сервера, предоставляющего OpenAI-совместимый API (эндпоинт), на который компонент отправляет HTTP-запросы. Суффикс `/v1` — это версионирование API: первая версия спецификации OpenAI определяет маршруты вида `/v1/chat/completions` и `/v1/models`. Сервер llama.cpp реализует именно эти пути, поэтому без префикса `/v1` запрос уйдёт на несуществующий маршрут и получит ошибку 404.

2. **Каким образом в Langflow происходит автоматическое формирование входных портов компонента Prompt при объявлении переменных в фигурных скобках?**
   При сохранении шаблона парсер выполняет разбор текста промпта и извлекает идентификаторы, объявленные в фигурных скобках (`{user_message}`). Для каждого найденного идентификатора Langflow динамически создаёт входной порт с тем же именем. Этот порт можно соединить с выводом любого другого компонента: при выполнении flow значение из порта подставляется на место переменной в шаблоне.

3. **В чем заключается физический и математический смысл параметра Temperature при сэмплировании токенов в LLM?**
   Модель выводит логиты (не нормированные оценки) для каждого токена словаря; перед softmax они делятся на температуру T. При T→0 распределение вероятностей «острится» — выбирается токен с максимальным логитом (жадная, детерминированная генерация). При росте T распределение сглаживается: вероятность распределяется шире, случайность выбора увеличивается, растёт энтропия и разнообразие ответов. Физически это аналог тепловой энергии в статистической механике — «возбуждённость» выборки.

4. **Какую роль выполняет системный промпт (System Message) и чем он отличается от пользовательского (User Message)?**
   Системный промпт задаёт роль, стиль и правила поведения модели на весь диалог: он является инструкцией, которая формируется до сообщений пользователя и определяет контекст взаимодействия (например, «отвечай строго на русском»). User Message — это конкретный запрос пользователя в рамках одного обращения. System Message управляет поведением как константа сессии, а User Message несёт изменяющуюся задачу; формат сообщения различается полем role в API.

5. **Каким образом переключатель Stream влияет на протокол взаимодействия между клиентом и сервером генерации?**
   При Stream=False сервер генерирует весь ответ целиком и возвращает его одним HTTP-ответом — клиент ждёт до завершения. При Stream=True соединение остаётся открытым, и ответ передаётся потоково фрагментами (чанками, SSE-событиями) по мере генерации каждого токена: пользователь видит текст инкрементально, воспринимаемая задержка первого символа минимальна. Протокол при этом тот же HTTP, меняется только способ доставки тела ответа.
