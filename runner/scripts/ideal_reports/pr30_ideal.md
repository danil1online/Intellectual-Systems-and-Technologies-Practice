### Шаг 2. Конвейер индексации (Ingestion)

Создан flow `Практическая 30 - Локальный RAG`. Компоненты ветви индексации:

1. **Data → Read File** — поле `file_path` = `/app/data/knowledge_base.txt`;
2. **Text Splitters → Recursive Character Text Splitter** — `Chunk Size = 500`, `Chunk Overlap = 50`;
3. **Embeddings → Embedding Model** (OpenAI Compatible) — Base URL `http://istp-embeddings:8021/v1`, модель `paraphrase-multilingual-MiniLM-L12-v2` (мультиязычная, работает на CPU);
4. **Knowledge Base** — векторное хранилище: приём чанков от сплиттера и модели эмбеддингов, параметр `top_k = 4`.

Связи: Read File → Splitter → Knowledge Base; Embedding Model подключён к порту эмбеддингов Knowledge Base.

### Шаг 3. Конвейер поиска и генерации (Retrieval)

Компоненты ветви генерации: **Chat Input**, **Knowledge Base** (режим поиска), **Prompt Template**, **OpenAI Model** (Base URL `http://192.168.2.83:8080/v1`, модель `qwen2.5-3b-instruct-q4_k_m.gguf`), **Chat Output**.

Шаблон промпта:

```text
System: Ты — аналитический ассистент. Отвечай на вопрос ПОЛЬЗОВАТЕЛЯ строго на основе предоставленного КОНТЕКСТА. Если в контексте нет ответа, скажи: «В документах информация отсутствует».

{context}
```

Связи: Chat Input → `question` (Prompt) и `Search Query` (Knowledge Base); Search Results (Knowledge Base) → `context` (Prompt); Prompt → OpenAI Model → Chat Output.

## Контрольные вопросы

1. **В чем заключается ключевое отличие архитектуры RAG от дообучения (Fine-Tuning) языковой модели?**
   В RAG знания хранятся во внешнем векторном индексе и подаются модели в контекст на момент каждого запроса: параметры модели при этом не изменяются, база знаний обновляется без переобучения. Fine-Tuning «запекает» знания непосредственно в веса (параметры) модели — требуется набор данных, вычислительные ресурсы и время обучения; адаптация к новым фактам означает новое дообучение. RAG проще верифицировать (можно показать источник), Fine-Tuning меняет само поведение модели.

2. **Почему при разбиении документа на чанки критически важно использовать параметр перекрытия (Chunk Overlap)?**
   Без перекрытия предложение или смысловая конструкция, разорванная границей чанка, попадает в два соседних фрагмента по частям: возникает потеря контекста, и семантический поиск может вернуть неполный, бессмысленный кусок. Параметр перекрытия дублирует хвост предыдущего чанка в начало следующего (целенаправленное дублирование), сохраняя целостность смысла на стыке. Цена — небольшой избыток данных и чуть более высокий расход токенов при генерации.

3. **Что такое векторный эмбеддинг и какая математическая мера используется для поиска релевантных чанков в векторном пространстве?**
   Эмбеддинг — это числовой вектор фиксированной размерности, который модель-эмбеддер вычисляет для текста и который компактно кодирует его смысл: близкие по смыслу тексты оказываются рядом в векторном пространстве. Поиск релевантных чанков выполняется по мере сходства — обычно косинусному расстоянию (или скалярному произведению) между вектором запроса и векторами чанков; альтернатива — евклидово расстояние. Чанки с наибольшим сходством (top-k) попадают в контекст промпта.

4. **Какие проблемы возникают при слишком маленьком (Chunk Size = 50) и слишком большом (Chunk Size = 4000) размере чанка?**
   При Chunk Size = 50 фрагменты теряют самостоятельный смысл: потеря контекста приводит к тому, что поиск возвращает шумовые нерелевантные куски, а модель не может составить из них связный ответ. При Chunk Size = 4000 в один чанк попадает много текста: релевантность размывается (вектор усредняет несвязанные разделы), в промпт уходит большой объём нерелевантных токенов — растёт стоимость запроса и снижается точность ранжирования. Размер 500/перекрытие 50 — разумный баланс для регламентных документов.

5. **Каким образом системный промпт предотвращает галлюцинации модели при отсутствии нужного ответа в базе знаний?**
   Системный промпт ограничивает модель рамками предоставленного контекста: инструкция «отвечай строго на основе КОНТЕКСТА» запрещает использовать внутренние (возможно, устаревшие или вымышленные) знания как источник. Дополнительно задаётся явное правило поведения при отсутствии информации — «скажи: В документах информация отсутствует», то есть управляемый отказ вместо выдумывания фактов. Таким образом контекст становится единственным допустимым источником ответа.
