## 📚 Краткая теоретическая информация  

Автоматическое распознавание речи (ASR) превращает аудиосигнал в текст. Ключевая сложность задачи – шумы, акценты, вариативность произношения.

Метрика WER показывает долю ошибок на уровне слов. Её формула:

$$
  WER = \frac{S + D + I}{N},
$$

где 𝑆 – количество замен, 𝐷 – удалений, 𝐼 – вставок, 𝑁 – число слов в эталонном тексте.

Метрика CER отражает ошибки на символах:

$$
  CER = \frac{S_c + D_c + I_c}{N_c},
$$

где индексы 𝑐 обозначают подсчёт на уровне символов.

## 🧪 Примеры и задания

### 🧪 Пример 1. Распознавание речи. Wav2Vec2 (HuggingFace)

Ниже — пример скрипта `hf_wav2vec2_asr.py`, который использует модель Wav2Vec2.

```python
#!/usr/bin/env python3
# file: hf_wav2vec2_asr.py

import os
# 1. Принудительно направляем весь Hugging Face в вашу папку
os.environ["HF_HOME"] = "/hf-cache"
# 2. Включаем глобальный офлайн-режим (запрещает любые сетевые запросы)
os.environ["HF_HUB_OFFLINE"] = "1"
os.environ["HF_DATASETS_OFFLINE"] = "1"
import torch
import soundfile as sf
from jiwer import wer, cer
from transformers import Wav2Vec2ForCTC, Wav2Vec2Processor

MODEL_ID = "facebook/wav2vec2-large-960h-lv60-self"
AUDIO_DIR = os.path.expanduser("~/data/asr/audio")
TRANS_DIR = os.path.expanduser("~/data/asr/transcripts")

# 1) Загрузка модели и процессора
processor = Wav2Vec2Processor.from_pretrained(MODEL_ID)
model     = Wav2Vec2ForCTC.from_pretrained(MODEL_ID).to("cuda" if torch.cuda.is_available() else "cpu")

refs, hyps = [], []

for fn in sorted(os.listdir(AUDIO_DIR)):
    if not fn.endswith(".wav"):
        continue

    utt = os.path.splitext(fn)[0]
    wav, sr = sf.read(os.path.join(AUDIO_DIR, fn))

    # 2) Ресемплинг (если нужно)
    if sr != 16000:
        import librosa
        wav = librosa.resample(wav, orig_sr=sr, target_sr=16000)

    # 3) Препроцессинг: VAD-trim (опционально)
    # wav, _ = librosa.effects.trim(wav, top_db=20)

    # 4) Токенизация и вывод логитов
    input_values = processor(wav, sampling_rate=16000, return_tensors="pt").input_values
    logits       = model(input_values.to(model.device)).logits
    pred_ids     = torch.argmax(logits, dim=-1)
    transcription = processor.batch_decode(pred_ids)[0].lower().strip()

    refs.append(open(os.path.join(TRANS_DIR, f"{utt}.txt"), encoding="utf-8").read().lower().strip())
    hyps.append(transcription)

    print(f"{utt}  |  HYP: {transcription}")

# 5) Подсчёт метрик
print("WER:", wer(refs, hyps))
print("CER:", cer(refs, hyps))
```

**📖 Что происходит в коде**

- **Офлайн-режим**: `HF_HOME = "/hf-cache"` + `HF_HUB_OFFLINE=1` + `HF_DATASETS_OFFLINE=1` — модель уже предзагружена в образ, скрипт не будет пытаться ничего скачивать.
- `MODEL_ID = "facebook/wav2vec2-large-960h-lv60-self"` — **самообученная** (self-supervised, обучалась на 960 часах неразмеченной речи, а не дообучена под ASR) Wav2Vec2, объёмом ~1.26G. Именно поэтому модель выдаёт предупреждение «TRAIN this model on a down-stream task» (см. ниже).
- Архитектура: `Wav2Vec2ForCTC` = предобученный аудиэнкодер + линейная CTC-голова. `processor` делает две вещи: превращает аудио во входные фичи (16 кГц, log-mel-спектрограмма) и декодирует CTC-токены в текст.
- Цикл по `~/data/asr/audio/*.wav`:
  - `sf.read` — чтение аудио (выборки и частота дискретизации);
  - если частота не 16 кГц — `librosa.resample` (LibriSpeech уже 16 кГц, это страховка);
  - **закомментированный этап** `librosa.effects.trim(wav, top_db=20)` — это VAD: отсечение тишины в начале/конце (уровни ниже максимума на 20 дБ). Это ровно тот «этап фильтрации», который просят добавить в задании;
  - `processor(wav, sampling_rate=16000)` — входные фичи; `model(...).logits` — пофреймовые логиты по словарю; `torch.argmax` — жадное декодирование по фреймам; `processor.batch_decode` — схлопывает «пустоты» (blank) и подряд идущие повторы в слова (так работает CTC-декодирование);
  - `.lower().strip()` — нормализация регистра, чтобы гипотезу можно было сравнивать с эталоном;
  - `refs` — эталонные тексты из `transcripts/{utt}.txt` (по одному файлу на фразу); `hyps` — гипотезы модели.
- `jiwer.wer(refs, hyps)` и `jiwer.cer(refs, hyps)` — выстраивают пары текстов по edit-расстоянию (подсчёт замен S, удалений D, вставок I) и считают WER (на словах) и CER (на символах) по формуле из теории.

### 🧪 Пример 2. Распознавание речи. Whisper (OpenAI)

Ниже — пример скрипта `whisper_asr.py`, который использует модель Whisper (размер 139M).

```python
#!/usr/bin/env python3
# file: whisper_asr.py

import os
# 1. Принудительно направляем весь Hugging Face в вашу папку
os.environ["HF_HOME"] = "/hf-cache"
# 2. Включаем глобальный офлайн-режим (запрещает любые сетевые запросы)
os.environ["HF_HUB_OFFLINE"] = "1"
os.environ["HF_DATASETS_OFFLINE"] = "1"
import whisper
from jiwer import wer, cer

model = whisper.load_model("base")  # можно взять tiny, small, medium, large
AUDIO_DIR = os.path.expanduser("~/data/asr/audio")
TRANS_DIR = os.path.expanduser("~/data/asr/transcripts")

refs, hyps = [], []

for fn in sorted(os.listdir(AUDIO_DIR)):
    if not fn.endswith(".wav"):
        continue

    utt = os.path.splitext(fn)[0]
    result = model.transcribe(os.path.join(AUDIO_DIR, fn), language="en", fp16=False)
    hyps.append(result["text"].lower().strip())
    refs.append(open(os.path.join(TRANS_DIR, f"{utt}.txt"), encoding="utf-8").read().lower().strip())
    print(f"{utt}  |  HYP: {result['text']}")

print("WER:", wer(refs, hyps))
print("CER:", cer(refs, hyps))
```

**📖 Что происходит в коде**

- Офлайн-режим тот же: модель предзагружена в образ.
- `whisper.load_model("base")` — Whisper (OpenAI), **end-to-end энкодер-декодер** (в отличие от CTC у Wav2Vec2): энкодер представляет аудио, а декодер с кросс-вниманием сам «написывает» текст последовательно. `base` — компактный из стандартных размеров (~139M; есть также tiny/small/medium/large).
- `model.transcribe(file, language="en", fp16=False)`: `language="en"` фиксирует язык (детектирование не включено); `fp16=False` — выключает половинную точность: GPU в образе нет, работаем на CPU, где fp16 нестабилен. Результат — словарь, `result["text"]` — распознанный текст; **модель сама добавляет пунктуацию и регистр**.
- `refs`/`hyps` и `jiwer` — то же самое, что в примере 1.

Запуск:

```bash
python whisper_asr.py
```

Результат работы:
```bash
WER: 0.22033898305084745
CER: 0.06396255850234009
```

**📌 Ожидаемый результат**
Две строки с метриками: `WER ≈ 0.22` и `CER ≈ 0.06` — заметно хуже, чем у Wav2Vec2 (см. таблицу и разбор ниже).

Ниже представлена сравнительная таблица:
|               | Wav2Vec2 | Whisper (OpenAI) |
|---------------|----------------------------|-----------------------------|
| Объём модели | 1.26G | 139M |
| WER | 0.017 | 0.220 |
| CER | 0.006 | 0.064 |

Почему у Whisper на этом наборе метрики заметно хуже?

1. Whisper **сам добавляет пунктуацию и регистр** (модель их генерирует), а в эталонных текстах LibriSpeech их нет — jiwer считает эти лишние знаки вставками.
2. Модель `base` почти в 9 раз меньше (139M против 1.26G).
3. Фразы короткие: при малом числе слов/символов каждая ошибка сильнее отражается в метрике.

Вывод — не «Whisper хуже», а то, что метрики сопоставимы только при равных условиях (одни и те же 10 фраз, одна и та же нормализация к нижнему регистру). Компактная модель привлекательна скоростью и малыми затратами, но на чистом наборе большую точность даёт большая.

**💡 Как подойти к заданию**

**Подпункт 1. Этап фильтрации.**
- Место вставки — в цикле по файлам, после ресемплинга и до вызова `processor(...)`. В коде примера уже есть готовый (закомментированный) этап — VAD: `librosa.effects.trim(wav, top_db=20)` (отсекает тишину, уровни ниже максимума на 20 дБ). Другие простые варианты — `librosa.util.normalize` (нормировка уровня) или `librosa.effects.preemphasis` (предвыделение).
- Важно: одно и то же предобращение применяйте и к чистому, и к зашумлённому набору — иначе сравнение нечестное.
- Оговорка: полноценного «денойзинга» в librosa нет — выигрыш дают в первую очередь отсечение тишины и нормировка.

**Подпункт 2. Чистое vs зашумлённое.**
- «Зашумлённого» аудио в датасете нет — его нужно создать самому: прочитать чистый wav и добавить белый гауссов шум `noisy = wav + level * np.random.normal(0, 1, len(wav))` (например, уровни 0.001, 0.005, 0.02), сохранив результат в отдельные папки (`audio_noisy_0001/` и т.д.).
- Параметризуйте скрипт через argparse (`--audio-dir`, `--transcripts-dir`) и прогоните один и тот же конвейер на каждом наборе — сам подсчёт метрик менять не нужно.
- Сведите таблицу «уровень шума | WER | CER» и опишите тренд: с ростом уровня растут обе метрики, на высоких уровнях ошибки становятся в основном удалениями и вставками.

**Подпункт 3. Влияние длины.**
- На 10 фразах прямой контраст «короткие vs длинные» слаб, поэтому практические варианты:
  - **Пословные/пофразные метрики**: `jiwer.wer(ref, hyp)` работает и для одной пары — посчитайте WER/CER для каждой фразы отдельно и сгруппируйте по длительности (`librosa.get_duration(y, sr=16000)`);
  - **Раскрой**: разрежьте длинные фразы на куски (простой срез numpy-массива по числу сэмплов) и сравните метрику на кусках с метрикой на целых;
  - **Собственные записи** разной длины, если есть возможность.
- Вывод формулируйте как тенденцию: из-за малой выборки (10 фраз) статистика ненадёжна.
