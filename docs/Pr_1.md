## 📚 Теоретические основы

### История Git

Разработка Linux в начале 2000-х осуществлялась в рамках системы BitKeeper. В 2005 году BitKeeper стал платным, и Линус Торвальдс создал новую систему контроля версий. Ключевые характеристики:

- поддержка нелинейного развития
- распределённая разработка: каждый разработчик имеет локальную копию полной истории
- совместимость с существующими системами и протоколами
- эффективное управление крупными проектами
- аутентификация истории: гарантирует идентичные обновления кода
- подключаемые стратегии слияния

Распределённые системы контроля версий (DVCS) стали важнейшими инструментами для совместной разработки ПО. Git — одна из самых популярных.

### Что такое Git?

Git — бесплатная распределённая система контроля версий под лицензией GNU GPL. Каждый разработчик получает полную копию репозитория на своём компьютере. Внесённые изменения можно синхронизировать с удалённым сервером.

### GitLab

GitLab — платформа DevOps, предоставляющая доступ к репозиториям Git, систему управления исходным кодом. Разработчики могут:

- Просматривать код, оставлять комментарии
- Работать со своей локальной копией кода
- Осуществлять ветвления и слияния
- Использовать CI/CD для тестирования и доставки

Другие платформы: GitHub, BitBucket.

### Основные термины

- *Протокол SSH* — метод безопасного удалённого входа.
- *Репозиторий* — место, содержащее папки проекта с контролем версий.
- *Форк / fork* — копия репозитория на сервере GitLab.
- *Merge request (MR)* — запрос на рассмотрение и утверждение изменений.
- *Working directory* — рабочая директория, связанная с Git-репозиторием.

### Основные команды Git

- *git add* — перемещает изменения из рабочего каталога в staging area.
- *git status* — состояние рабочего каталога и снимок изменений.
- *git commit* — снимок изменений и фиксация в проекте.
- *git reset* — отмена изменений в файлах.
- *git log* — предыдущие изменения в проекте.
- *git branch* — создание изолированной среды для изменений.
- *git checkout* — просмотр и изменение веток.
- *git merge* — соединение веток.
- *git push* — отправка изменений на сервер.
- *git pull* — получение обновлений с сервера.

### Ветвление (Branch)

В Git файлы хранятся в ветках. Основная ветка (main) — развертываемая версия кода. При планировании изменений создаётся новая ветка как точная копия исходной. Изменения в дочерней ветке не попадают автоматически в main.

### Коммит (Commit)

Фиксация изменений. Разработчик должен написать содержательный комментарий:

- Не заканчивайте сообщение точкой.
- Не более 50 символов — для подробностей используйте расширенное описание.

### Merge Request

Изменения в ветке публикуются только после утверждения:

1. Создаётся merge request.
2. Код рассматривается и утверждается.
3. Ветка сливается с main.

### Fork и Clone

**Clone** — локальная копия удалённого репозитория:

```bash
git clone git@gitlab.example.com:user/repo.git
```

**Fork** — полная копия репозитория на GitLab-сервере. Проект-родитель называется *upstream*.

## 📌 Программа работы (см. [Основные команды](#основные-команды))

В терминале JupyterLab:

1. Откройте терминал и перейдите в корневой каталог клонированного репозитория `project` (если еще этого не сделали)
2. В терминале создайте ветку `newbranch`
3. Переключитесь на неё
4. Создайте файл `newbranchfile` с любым содержимым
5. Добавьте файл и зафиксируйте изменения
6. Отмените последний коммит (`git revert HEAD --no-edit`)
7. Создайте файл `newgoodfile`
8. Добавьте и зафиксируйте его
9. Переключитесь на `main`
10. Объедините `newbranch` с `main`
11. Отправьте изменения на сервер (`git push`)
12. Удалите ветку `newbranch`
13. Проверьте `git log` — история должна содержать все ваши коммиты

**Результат:** вывод `git log`, показывающий ветку, merge и коммиты.

### Основные команды

**Проверка статуса и история:**

```bash
git status
git log
```

> 💡 Для выхода из `git log` нажмите `q`.

**Создание и переключение ветки:**

```bash
git branch feature-1
git checkout feature-1
```

> 💡 Можно создать и сразу перейти в ветку:
> ```bash
> git checkout -b feature-1
> ```

**Создание файла, добавление и фиксация:**

```bash
echo "# Practice 1" > reports/Pr_1/test.md
git add reports/Pr_1/test.md
git commit -m "Add test.md to Practice 1"
```

**Откат изменений:**

```bash
git revert HEAD --no-edit
```

**Слияние ветки с main:**

```bash
git checkout main
git merge feature-1
git log
```

**Отправка изменений на сервер:**

```bash
git push origin main
```

**Получение обновлений:**

```bash
git pull origin main
```

**Удаление объединённой ветки:**

```bash
git branch -d feature-1
```

5. Загрузите в репозиторий и отправьте:

- Добавляем все изменения всех файлов в историю git  
```bash
git add .
```

```bash
git commit -m "Pr_1 report"
```
- Отправляем данные на сервер
```bash
git push
```
